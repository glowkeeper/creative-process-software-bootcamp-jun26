# React Resources

## About This Guide

The Software Development Bootcamp is designed to be self-contained.

You do **not** need any of the resources below to complete the course successfully.

However, if today's topic has sparked your curiosity, these carefully selected resources provide an excellent place to continue exploring React.

The aim is quality rather than quantity.

## Official Documentation

### React Documentation

https://react.dev

The official React documentation is one of the best programming resources available.

Unlike many documentation sites, it explains *why* React works the way it does rather than simply listing APIs.

If you only use one external React resource, use this one.

### Recommended Reading

Read these in roughly this order:

1. **Thinking in React**  
   https://react.dev/learn/thinking-in-react

2. **Your First Component**  
   https://react.dev/learn/your-first-component

3. **Importing and Exporting Components**  
   https://react.dev/learn/importing-and-exporting-components

4. **Passing Props to a Component**  
   https://react.dev/learn/passing-props-to-a-component

5. **Responding to Events**  
   https://react.dev/learn/responding-to-events

6. **State: A Component's Memory**  
   https://react.dev/learn/state-a-components-memory

7. **Rendering Lists**  
   https://react.dev/learn/rendering-lists

These topics closely match the concepts introduced during this bootcamp.

## Browser Tools

### React Developer Tools

https://react.dev/learn/react-developer-tools

The React Developer Tools browser extension allows you to inspect React components while your application is running.

It helps you understand:

- Component hierarchies
- Props
- State
- Application structure

This is an excellent way to explore both the course reference application and your own projects.

## Final Thoughts

The most valuable React resources are often the ones you already have:

1. Your own application.
2. The course reference application.
3. The official React documentation.

Professional developers rarely memorise everything.

Instead, they build software, experiment, read documentation and continually refine their understanding.
